+ 速览

一款面向高规则密度场景的薪资分配策略工具。相比强调“贪心算法”，它更体现我如何把重复、易错的流程做成双端可用的小产品。

01背景与用户

使用场景适用于发薪、现金分发、批量换钞与柜台场景。

核心问题人工拆分慢、余数易错、批量名单校对成本高。

本轮范围围绕单笔与 Excel 批量发薪的输入、面额选择、余数和固定导出列定义口径；不处理现金库存或跨机构调拨。

为什么做我在意的不是算法名词本身，而是把反复发生的规则判断变成稳定可交付的小产品。

典型用户发薪协助人员／柜台操作人员（脱敏角色）

情境
批量发薪前，需要按固定票面拆分金额并核对名单。
需要
确认每笔拆分无余数、批量结果口径一致，并可直接导出。
风险
分发时容易出现余数、漏项或不同操作人员口径不一致。

02方案与取舍

我负责的部分我负责需求梳理、拆分规则定义、批量导入导出流程设计、异常校验策略，以及网页端与小程序端口径统一。

关键取舍我优先保证“算得对、导得出、能批量复核”，而不是堆叠复杂交互，确保下游流程稳定接住输出结果。

方案路径

01勾选面额
02贪心拆分
03余数校验
04批量导出

勾选可用面额 → 按从大到小贪心拆分 → 校验余数与异常金额 → 一键导出固定列顺序。

03架构与代码

入口

  • 网页 · web/index.html（GitHub Pages）
  • 微信小程序 · miniapp/
  • Python CLI · money_classify.py

共用规则

  • classify(amount, denominations) 贪心拆分
  • parseSalary 金额解析 · 非法返回 NaN
  • isHeaderRow / isEmptyRow 表格识别
  • 余数单独返回，由界面决定提示或阻断

批量与导出

  • SheetJS 读 xlsx / xls / csv（本地解析，不上传）
  • rowsToBatchRows · 坏行记 Excel 行号
  • buildWorkbook 固定列导出 · 配钞结果

三个入口共用同一份拆分与解析规则，规则改一处三端一致。名单只在设备本地解析，不经过任何服务器；坏行记录行号而不是整表失败，操作员能直接回去改。

我写的模块

miniapp/utils/classify.js · web/index.html
贪心拆分、金额解析、表头 / 空行识别；网页端内联同一套函数
miniapp/utils/excel.js
SheetJS 读写、批量行解析与坏行记录、固定列导出
miniapp/pages/index · pages/batch
单笔配钞与面额勾选；批量导入、重算、导出并用 wx.openDocument 打开
web/money_classify.py
同一拆分规则的 Python 命令行版本，用于快速核对
.github/workflows/pages.yml · miniapp/docs/*.md
GitHub Pages 自动部署；小程序的 setup / qa / release 三份检查清单
