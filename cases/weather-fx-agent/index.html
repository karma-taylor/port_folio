01背景与用户

使用场景适用于报销、差旅、柜台咨询和跨境结算场景；Agent 层适合在终端里快速问汇率与天气。

核心问题汇率来源不一致、人工换算易错、弱网场景仍需出数；Agent 层要处理模型切换、工具失败与配置错误。

本轮范围围绕工具契约、调用循环、模型来源切换、币种方向、汇率来源与弱网回退定义口径；不覆盖交易执行、实时行情承诺或合规报价。

为什么做这个项目是一次“最小工具调用 Agent + 结果可信度设计”的练习，而不是单纯做一个换算器。

典型用户跨境结算／报价协助人员（脱敏角色）

情境
提交报价或报销前，需要确认汇率换算方向、来源和结果。
需要
得到可追溯的换算结果；弱网时也能明确知道系统采用了何种降级结果。
风险
不透明数字或换算方向错误会把核对压力留到提交之后。

02方案与取舍

我负责的部分我负责 Agent 的工具契约与调用循环、模型来源切换与失败诊断，以及 Web 端的汇率口径、换算纠偏规则、缓存与弱网策略。

关键取舍工具失败不中断会话，而是把 ok:false 回传给模型解释；Web 端不做“黑盒换算结果”，明确展示所用来源和汇率口径。

方案路径

01用户自然语言
02模型选工具
03执行并回填
04生成可复核回答

用户自然语言 → 模型判断是否需要工具 → 执行 get_weather / get_exchange_rate → 结果以 role: tool 回填 → 模型生成带来源的回答；Web 端则是 输入币种金额 → 选择参考汇率 → 方向互换取倒数 → 输出结果与口径说明。

03架构与代码

CLI Agent · agent.py

  • 读取 .env：API Key / BASE_URL / MODEL
  • chat.completions(tools=TOOLS, tool_choice=auto)
  • tool_calls → 本地执行 → role: tool 回填
  • 无 tool_calls 时输出最终回答
  • 401 / 429 / 404 / 断网分别给可操作提示

工具

  • get_weather(city) · 公开天气 API
  • get_exchange_rate(base, target, amount)
  • 返回结构化 JSON，失败也带 ok:false

Web 换算器 · webapp.py

  • FastAPI /api/convert · 银行系数表
  • 固定汇率：方向互换自动取倒数
  • PWA + Service Worker 离线可用
  • 访问统计与每日 Excel 导出
  • Docker → Hugging Face Spaces

两层各自独立：Agent 层只负责「什么时候调哪个工具、怎么把结果说清楚」，模型可在 OpenAI、DeepSeek 与本机 Ollama 之间切换；Web 层不走模型，保证弱网和离线时换算仍可用。

我写的模块

agent.py
function calling 主循环、两个工具的 JSON Schema 定义、Ollama 模型存在性检查、针对 401 / 429 / 404 的诊断提示
webapp.py
FastAPI 换算接口、银行汇率系数、历史曲线接口、访问统计与定时 Excel 导出
templates/index.html · static/sw.js
换算 UI、固定汇率快照与人民币多档预设（localStorage）、Service Worker 离线缓存
Dockerfile · render.yaml
容器化与 Hugging Face Spaces / Render 部署配置

这个项目没有评测集，不写准确率或耗时数字。它的价值是一个能读完的最小工具调用 Agent 实现，以及 Web 端对结果可复核与弱网可用的处理。

  • CLI Agent：OpenAI function calling 循环，两个工具按需调用，模型可换（OpenAI / DeepSeek / Ollama）
  • Web 换算器：FastAPI + PWA，多银行参考、固定汇率方向取倒数、弱网缓存降级
  • 工具失败回传给模型解释，而不是让会话崩溃
